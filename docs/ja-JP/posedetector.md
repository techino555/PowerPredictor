# メモリ効率を意識した画像キャプチャ

一般的なカメラアプリでは、シャッターを切った後に画像データをJPEG等のファイルとして保存し、それを再度UIImageとして読み直す処理がよく見られるが、リアルタイムな推論を行う本アプリでは一旦画像を実機に出力するという想定はしなかった。出力するとデータが貯まるのでその廃棄に手間取るからだ。

そこで、AVCapturePhotoCaptureDelegateから得られるAVCapturePhotoに対して、直接メモリ上でCGImageを取り出すメソッド（cgImageRepresentation()）を活用した。無駄なエンコードやファイル書き出しを一切挟まず、メモリ上に展開されたピクセルバッファをそのまま後続の処理へ渡すことで、省メモリかつ低遅延なパイプラインを実現した。

# 人物検出とセグメンテーション

カメラから取得したフレームに対して、Appleの機械学習フレームワークであるVision Frameworkを適用し、人物の位置特定とシルエットの切り抜きを行う。本アプリでは主に以下の2つのリクエストを利用している。

 1. 人物矩形検出（PersonDetector）: 画像内に人間が存在するかを判定し、バウンディングボックス（CGRect）を高速に算出する。
 2. 人物セグメンテーション（PersonSegmenter）: 人物の輪郭（マスク）をピクセル単位で正確に抽出し、背景と人物領域を分離する。

# PersonDetectorの実装

人物検出には、Vision FrameworkのVNDetectHumanRectanglesRequestを使用する。このバウンディングボックス情報は、
画面上で後に説明する人物をロックオンするHUDマーカーの位置決定に利用した。HUDマーカーは人物をトラッキングする様子を示すための
三角形で人を囲っている演出部分になるところだ。本家に近づけるために採用した。

# スカウター演出の試行錯誤

VNGeneratePersonSegmentationRequestを用いて人物領域のマスクを取得し、Appleのフレームワークの一つであるCore Imageを利用してスカウター特有の色彩加工を施す。当初、切り抜いた人物マスクに対して単色の黄土色カラーレイヤー（ocherFg）をそのままブレンドしていた。しかしこれを行うと、人物の顔の陰影、服のシワ、明暗の立体感がすべて塗りつぶされてしまい、のっぺりとした不自然なシルエットになってしまった。不透明度（opacity）を下げてもコントラストがぼやけてしまう。そこで単色で塗りつぶすのではなく、元画像の輝度・明暗情報を残したまま色相をシフトさせる着色画像（coloredFg）を生成し、それを人物マスクを通して背景（薄黄色）と合成する方式を採用した。これにより、顔の輪郭や筋肉の凹凸感を鮮明に残したまま、滑らかな黄土色にハイライトされた近未来的な解析画面を作り出すことができた。


# 無制限検出を防ぐための制御

カメラフレーム内に人物が映っていても、距離が遠すぎたり、画面端に見切れていたり、姿勢が不完全な状態で無制限に検出・測定処理を走らせると、誤検出や不要な負荷の原因となる。そこで本アプリでは、`FrameValidator` と `PoseValidator` による2段階の検証を行い、測定に適した状態のみを受け入れる制御を導入している。

# VisionPipelineによる統合

これらの検出・加工処理を1つのパイプラインとして束ねるのがVisionPipelineである。Apple標準のAVFoundationとVision、Core Imageを組み合わせることで外部ライブラリを増やすことなく、高速な人物トラッキングとスカウター風の視界の再現とした。
