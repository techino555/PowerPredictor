# iOSアプリでの戦闘力モデル実行、出力とUI構成

前章では、DINOv3を用いて人物画像から768次元のEmbeddingを抽出するパイプラインを構築した。
本章では、その特徴量から戦闘力数値を算出する軽量回帰モデルの組み込みと、スカウターの世界観を体現するUIの実装および状態管理について解説する。

## スカウターUIの画面構成と状態管理

スカウターアプリの体験において本家に近づかせるために「ターゲットを捕捉し、照準が定まり、内部で高速にスキャン計算が行われ、最後に数値が確定する」という一連の演出を再現するようにした。

### ScanStateによる状態遷移

この体験を破綻なく制御するため、ScanViewModelに厳密な状態遷移（ScanState）を定義した。

 * idle: 通常待機状態。カメラプレビューと「SCAN」ボタンのみを表示。
 * detecting: 人物捕捉状態。ターゲットマーカー（四隅の三角HUD）が表示され、人物が黄土色にハイライトされる。本家に近い演出をする状態
 * analyzing: 解析実行中状態。プログレスバーが現れ、戦闘力の数字が高速にパラパラとランダム変動（カウント演出）する。
 * complete: 判定完了状態。画面が薄黄色に染まり、確定した戦闘力スコアが上部に太字で出現する。

### 音と処理・アニメーションの同期

ユーザーがSCANボタンを押した瞬間を引用通り演出するため、効果音の再生と画面演出、バックグラウンド推論を緻密に同期させた。ちょっとズレることもあるがコードでタイミングを合わせている。下記のフローで戦闘力表示が演出される。なお使った効果音はこちら[^スカウター]から拝借した。これも同意が必要な資源のため活用の際には引用を参照すること。

```text
SCANボタン押下
    ↓
効果音再生開始（ピピピピ…というスキャン音）
    ↓
.analyzing 状態へ遷移（ProgressView表示 & 数字のパラパラ演出開始）
    ↓
バックグラウンドでDINOv3およびLinearPredictor推論実行
    ↓
Task.sleep で約3秒間の劇的な演出ウェイトを維持
    ↓
スキャン効果音終了 & 確定音（ピコン！）再生
    ↓
.complete 状態へ遷移 & 戦闘力スコア確定表示
```

ScouterStore内では以下のように状態遷移とウェイト制御を記述し、推論の速さにあえて一定の溜めを作ることで、本家のようなスキャン体験を演出した。

```swift
// ScouterStore内での同期制御イメージ
viewModel.setAnalyzing()
soundPlayer.playScanningSound()

// バックグラウンドで推論を行いつつ、演出のために約1〜3秒間待機
let score = try await runInferencePipeline(image: targetImage)
try await Task.sleep(nanoseconds: 1_000_000_000)

soundPlayer.stopScanningSound()
soundPlayer.playCompleteSound()
viewModel.finishScan(score: score)
```

### スカウター演出を支えるUIコンポーネント

UIは一般的なiOSアプリと同様にSwiftUIのViewで構成されており、その階層は以下のように分離・設計されている。

 1. HUDOverlayView: 画面端のフレームと、人物の周囲を囲む4隅の三角マーカーを描画。一番下の三角マーカーには、原作に準拠した「SET」の文字を刻印。いずれも本家に近づける演出のため。
 2. ScanOverlayView: ZStackを用いて、加工済みカメラプレビュー、HUDを状態に合わせて重ねて表示。
 3. PowerView: 戦闘力スコアと「FIGHT」のテキスト、評価ゲージを表示。

## UIフリーズと描画チラつきの解決

実装の過程では、SwiftUIと非同期推論の連携においていくつかの技術的課題が発生した。

### バックグラウンドスレッドへのオフロード

初期の実装では、SCANボタンを押した際にUIが一瞬固まり、数字の素早い繰り返しであるローディングアニメーションがスムーズに再生されない問題が発生した。原因は、DINOv3の推論処理や重みメモリ展開がメインスレッドをブロックしていたためである。これを解決するため、ScouterStore内の推論パイプラインを`Task.detached`を用いてバックグラウンドスレッドへ完全に逃がすリファクタリングを行った。これにより、メインスレッド側の描画レートを落とすことなく、解析中のカウントアップ演出を滑らかに動かすことが可能になった。

### Opacityによる表示チラつきの防止

また、detectingからanalyzingへ遷移する際、PowerViewの文字色をクリア（.clear）にする手法では、SwiftUIのレンダリングサイクルの都合で直前の数値が一瞬チラついて見えてしまう現象が発生した。この問題に対しては、個々のテキスト色ではなく、detecting状態ではPowerView全体の不透明度を`.opacity(0)`として完全に描画ツリー上で隠蔽し、analyzingに切り替わった瞬間に`.opacity(1)`で出現させる構造に改めることで、違和感のないクリアな表示タイミングを実現した。

このように一つ一つ動作確認を実施し積み重ねた結果、iPhoneでのスカウター風アプリ、PowerPredictorが完成した。
